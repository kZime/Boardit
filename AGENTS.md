# Boardit development guide for agents

This file is the high-signal entry point for automated and human-assisted development. Read the linked documents only when the task touches that area.

## Product and scope

Boardit is a modular-monolith note and publishing application being prepared for trustworthy AI editing and private-knowledge workflows. Preserve the current React/TypeScript and Go/Gin/GORM/PostgreSQL stack unless an approved ADR replaces it.

## Source-of-truth rules

- `backend/docs/api/api-contract-v1.yaml` is the API contract source of truth.
- `frontend/src/api/gen/**` is generated by Orval. Never edit generated files manually.
- Applied SQL migrations are immutable. Add a new numbered migration; never modify an applied migration.
- README files are entry points, not copies of architecture, testing, or operations documentation.

## Required dependency direction

```text
Gin/router -> HTTP handler -> noteapp use-case -> repository interface -> GORM adapter
```

- HTTP handlers parse input and translate errors; they do not own authorization, transaction, or save rules.
- GORM models stay in persistence code. UI, generated API models, and future AI modules do not depend on them.
- Any AI write must call the note application service. It must not update a note row directly.

## Data invariants

- Every accepted note has a monotonically increasing integer `version`.
- A note create or update writes the note, immutable revision, and outbox event atomically.
- Updates use optimistic concurrency. A stale `version` must conflict instead of overwriting newer content.
- Private resources and searches are scoped by `user_id`; inaccessible resources are reported as not found.
- AI output remains an `ai_candidate` until explicit acceptance. Candidate generation never overwrites `notes.content_md`.
- Workers must validate `(note_id, user_id, version)` and use deduplication keys.
- Refresh tokens are single-use server-side sessions. Rotation revokes the old session; logout revokes the current session.

## Frontend boundaries

- React Query owns server cache; feature hooks or local reducers own editing state.
- Token persistence lives in `src/auth/tokenStorage.ts`; Axios must not import React context.
- The editor tree, metadata dialogs, save coordination, and API pagination remain separate feature modules.
- Keep the editor route lazy-loaded. Treat the MDXEditor bundle as a known performance constraint.

## Change workflow

1. Read `docs/architecture.md` and the relevant ADR.
2. Add or update the lowest-level test that expresses the desired behavior.
3. Make the smallest cohesive change while preserving public behavior unless the task explicitly changes it.
4. If the OpenAPI contract changes, run `cd frontend && npm run orval` and commit the generated client.
5. If the schema changes, add matching PostgreSQL and SQLite `up`/`down` migrations and migration tests.
6. Run the gates in `docs/testing-strategy.md`.
7. Review `git diff --check`, generated drift, and unrelated user changes before committing.

Do not push, deploy, rewrite Git history, access production data, or make unresolved product decisions without explicit authorization.
